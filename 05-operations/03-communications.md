# Communications

ARGC defaults to written, asynchronous communication for anything that can wait — which is most things. Decisions are documented; verbal agreements are not club policy. Node leaders own information flow within their node. Cross-node communication goes through established channels, not informal threads that disappear.

## The Default

Written. Asynchronous. Specific.

This means: if you have something to communicate that will affect another member's work, write it down in the right place. Do not rely on a hallway conversation that the other person may remember differently. Do not send a message in an informal channel and assume it was received.

The format of communication is not about formality. It is about durability. If a decision or direction is not written somewhere retrievable, it does not exist for the purposes of accountability.

## Channels

| Channel | Use |
|---------|-----|
| **Platform** | XP records, evaluation logs, voting, official decisions |
| **GitHub Issues / PRs** | Technical decisions, code review, platform work |
| **Designated async channel** | Node updates, event announcements, inter-node coordination |
| **Direct message** | Time-sensitive bilateral communication only |

What does not count as official communication: group chats that are not archived, in-person conversations without a written follow-up, and any platform that ARGC does not officially use.

## What Goes Where

**Decisions** go on the platform. If a decision was made in a meeting, someone writes it up and posts it on the platform within 24 hours. If that does not happen, the decision was not made.

**Technical discussions** go on GitHub. If you are making a choice about the platform, make it in the PR or issue where the work lives.

**Operational updates** go in the designated async channel. Node status, event reminders, member changes — anything the club needs to know but does not need to vote on.

## What Is Not Communication

- A message in an informal group chat
- A verbal agreement in person
- An assumption that someone saw something because they were in the room

ARGC does not run on implied communication. If you need someone to know something, you make sure they know it — in writing, in the right place.

## Response Expectations

ARGC is asynchronous by default. This means there is no expectation of immediate response. The expectation is response within a reasonable window — 24 hours for operational matters, 48 hours for anything that requires thought.

If something is genuinely urgent, call it urgent explicitly. Everything cannot be urgent. If everything is, nothing is.
